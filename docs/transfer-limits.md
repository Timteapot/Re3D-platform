# 上传/下载并发与流量控制

更新时间：2026-10-08

## 目标和作用范围

平台对已认证用户的单张图片上传和重建产物下载执行两类独立限制：

- 并发租约：限制同一用户同时占用的上传处理或下载响应数量；
- 字节令牌桶：限制同一用户在一段时间内可以接收或发送的累计文件字节。

状态保存在 PostgreSQL，多个 API 进程共享同一裁决结果。普通 API 来源 IP 请求频率、认证专项限流、任务提交次数、逻辑存储配额和传输限制仍是不同控制面，不能互相替代。

## 默认配置

```dotenv
TRANSFER_WINDOW_SECONDS=3600
TRANSFER_UPLOAD_MAX_CONCURRENT=2
TRANSFER_UPLOAD_MAX_BYTES=2147483648
TRANSFER_DOWNLOAD_MAX_CONCURRENT=3
TRANSFER_DOWNLOAD_MAX_BYTES=4294967296
TRANSFER_LEASE_SECONDS=14400
```

这组默认值表示：令牌桶在 1 小时内连续补满，容量分别为上传 2 GiB、下载 4 GiB；同一用户最多同时处理 2 个上传和 3 个下载；异常遗留租约最多保留 4 小时。它们是首期开发基线，不是目标服务器的最终容量结论。production 必须显式提供所有值；就绪检查还要求上传和下载桶容量至少不小于单张上传上限。

同一部署中的所有 API 实例必须使用完全相同的传输配置。数据库保证并发裁决一致，但不能自动协调配置漂移；滚动发布修改这些值时应先完成配置一致性检查。

字节桶不是整点重置的固定窗口。每次裁决先根据距上次更新时间的秒数连续补充令牌，再预扣本次文件大小，所以不会在窗口边界允许瞬时双倍流量。调整容量时，数据库中的旧桶会在下一次请求中安全收缩或扩展到新容量。

## 数据库和并发合同

`0015_transfer_limits` 增加：

- `user_transfer_buckets`：每用户、每方向一个令牌桶，保存容量、剩余字节和更新时间；
- `user_transfer_leases`：每次获准传输一个租约，保存方向、预扣字节、获取和过期时间。

裁决事务先锁定 `users` 对应行，再清除当前方向的过期租约、统计活动租约、补充令牌并插入新租约。因此同一用户的并发请求会在 PostgreSQL 中串行裁决，不会因部署多个 API 进程而超发。不同用户仍可并行处理。

正常上传在图片校验/落盘结束时释放租约。正常下载通过 `FileResponse` 的响应后台任务释放租约；客户端中断也会进入响应收尾路径。API 进程崩溃或数据库短暂不可用时，租约由 `TRANSFER_LEASE_SECONDS` 提供有界恢复。该值应大于目标服务器压力测试中的最长合法传输时间，否则极慢传输可能在仍进行时释放并发容量。

## 上传裁决

FastAPI/Starlette 完成 multipart 解析后，路由从 `UploadFile.size` 取得文件实际字节并一次性申请上传租约和字节额度。获准后才进入既有 staging、大小、解码、像素、磁盘安全线和用户存储配额检查。无效图片、重复图片或后续存储失败不会返还字节令牌，因为请求体已经到达应用。

这个位置不能阻止恶意请求体先穿过公网和反向代理。Caddy 的 `request_body max_size` 负责单请求体早期拒绝；真实公开入口还必须提供连接数、请求速率、超时和大规模流量防护。应用层上传并发限制控制的是 multipart 解析后的业务处理，不是入口连接并发。

## 下载裁决

下载仍先完成任务所有权、成功终态、路径、大小和 SHA-256 复核，然后按清单中的完整产物大小申请下载租约并预扣令牌。获准后才构造文件响应。客户端中断、Range 请求或重复下载不会按实际发送量退款；这是保守的下载额度策略，可防止通过反复中断规避配额。

若单个文件大于当前方向的令牌桶总容量，请求会直接被拒绝且不提供 `Retry-After`，因为等待不能让桶容量超过配置上限。运维人员必须提高容量或改用经过单独设计的对象存储/分块下载合同。

## 429 合同

所有传输限制响应均包含 `Cache-Control: no-store` 和下列稳定错误码：

| 方向 | 原因 | `X-Re3D-Error-Code` | `Retry-After` |
|---|---|---|---|
| 上传 | 并发槽已满 | `UPLOAD_CONCURRENCY_LIMIT_REACHED` | 最早租约预计释放秒数 |
| 上传 | 字节令牌不足 | `UPLOAD_TRAFFIC_LIMIT_REACHED` | 补足令牌预计秒数；单文件超容量时省略 |
| 下载 | 并发槽已满 | `DOWNLOAD_CONCURRENCY_LIMIT_REACHED` | 最早租约预计释放秒数 |
| 下载 | 字节令牌不足 | `DOWNLOAD_TRAFFIC_LIMIT_REACHED` | 补足令牌预计秒数；单文件超容量时省略 |

前端应展示稍后重试提示，不能自动无限重试。429 不改变上传会话、任务终态或产物保留状态。

## 仍需在目标服务器验收

当前控制的是应用级业务并发和累计字节额度，不执行逐连接 Mbps 整形，也不是 DDoS 防护。公开开放前仍需：

1. 用代表性图片和真实产物测试 1、2、3 个同用户并发以及多用户并发，记录 API CPU、PostgreSQL 锁等待、数据盘和实际吞吐；
2. 令牌耗尽后验证 429、`Retry-After` 和恢复时间，并确认最长合法传输明显短于租约时长；
3. 在 Caddy 前或云入口配置连接/请求速率、超时、安全组及必要的 CDN/WAF，再验证大请求在到达 API 前被拒绝；
4. 根据目标网络上行、下行、磁盘吞吐和公平性要求调整默认值并归档测试证据。

因此该实现消除了“应用完全没有单用户传输边界”的缺口，但不能单独证明系统已经具备公开互联网抗流量攻击能力。
