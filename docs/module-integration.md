# 当前实现的系统作用与模块对接

## 1. 当前实现处于哪一层

当前代码完成了 React 登录/注册、数据库共享认证限流、脱敏认证审计及其保留期清理、邮箱验证与密码重置前后端闭环、本地 SMTP 捕获验收、真实图片上传、模拟/真实任务分流、受控产物下载、三分支 GLB 在线预览和真实 GPU 小数据集验收。它解决用户身份和会话、邮箱所有权、受保护前端路由、图片如何安全进入任务目录、任务如何被描述和持久化、Worker 如何独占资源，以及怎样监督真实子进程、验证并展示产物、生成结构健康评估。任务接口限流、任务数据保留期、生产邮件服务和资源采样仍未完成。

```text
React 前端（内容/认证/图片上传/任务/三维预览已实现）
    │  HTTP/SSE
    ▼
FastAPI（认证、稳定任务访问和开发任务创建接口已实现）
    │  写任务、请求和模拟输入
    ▼
PostgreSQL 状态机/租约（已实现）
    │  Worker 原子领取、续租和状态推进
    ▼
Windows Worker
    ├─ 契约校验（已实现）
    ├─ 路径和输入完整性（已实现）
    ├─ 队列化三分支模拟执行与模拟评估（已实现）
    ├─ 真实 Re3D dry-run（已实现）
    └─ 真实执行控制器（已实现并完成 GPU 小数据集验证）
          │
          ▼
Re3D v1.1.0 A-v4 / B-v2 / C
          │
          ▼
真实产物归一化/结构评估（已实现） → 查询/下载 API → 三维查看器（已实现）
```

## 2. 已实现模块的职责

| 当前模块 | 主要输入 | 主要输出 | 在完整系统中的作用 |
|---|---|---|---|
| React 前端骨架 | 用户导航和认证表单 | 会话状态、受保护页面 | 建立浏览器入口并固定令牌存储和 API 调用边界 |
| 上传服务 | multipart JPEG/PNG | 任务内图片、哈希与元数据 | 在入队前隔离、解码并校验用户输入 |
| JSON 契约 | API 任务数据 | request/event/result/evaluation 结构 | 固定前后端、Worker 和评估器共同语言 |
| 认证服务 | 注册和登录凭据 | 用户、access token、refresh session | 建立服务端可信用户身份和可撤销会话 |
| 认证安全层 | 登录/注册/验证/重置请求、可信代理与 SMTP 配置 | 一次性令牌、账户/身份/IP 限流桶、脱敏认证事件 | 抑制认证滥用，完成邮箱所有权与密码恢复，并按保留期维护最小安全记录 |
| `TaskLayout` | 数据根目录、job UUID | 安全任务路径 | 保证用户任务文件隔离，限定清理边界 |
| 输入完整性校验 | manifest、图片、请求哈希 | 通过或稳定错误 | 防止排队后输入被替换或目录混入其他文件 |
| 模拟 Worker | simulated 请求 | 三个最小 GLB、事件、结果 | 让 API 和前端在 GPU 接入前完成联调 |
| FastAPI 任务接口 | Bearer token、任务 UUID | 列表、详情、取消、SSE 和产物 | 稳定 `/api/v1/jobs` 各环境注册；模拟创建仍仅限 development/test |
| PostgreSQL 队列 Worker | 队列记录、资源租约 | 状态投影、三分支产物 | 验证 API 与独立执行进程的异步闭环 |
| 模拟评估器 | simulated pipeline result | evaluation.json | 验证评估契约，不生成虚假的真实质量分数 |
| 真实 Re3D 适配器 | real 请求、Re3D 安装、数据库租约 | 步骤事件、私有日志、三分支归一化产物 | 在取消、超时和租约丢失时终止进程树，并校验产物完整性 |
| 真实结构评估器 | result、SfM 指标、A/B 一致性清单 | evaluation.json | 用版本化阈值生成 pass/warning/fail；没有真值时不伪造绝对精度分数 |
| Three.js 查看器 | 受鉴权 GLB Blob、分支摘要 | 浏览器交互预览 | 在不暴露令牌和磁盘路径的前提下切换、检查三分支结果 |
| Re3D v1.1.0 目录接口 | work/output/log 精确路径 | 任务内运行文件 | 阻止不同用户任务散落或互相覆盖 |
| 原子写入与 SHA-256 | JSON、产物 | 完整文件和摘要 | 避免读取半文件，并支持篡改检测和幂等复用 |

## 3. 与后续模块如何对接

### 用户与鉴权模块

注册登录模块管理用户身份、密码哈希、短期 access token 和可轮换 refresh session。登录前由 PostgreSQL 中的账户/IP 桶执行共享限流，注册前由用户名/邮箱/IP 桶限制有效尝试；认证结果写入仅含 HMAC/SHA 指纹和原因码的事件表，独立维护命令按保留期清理旧事件和闲置桶。稳定任务接口和开发任务创建接口都从服务端验证的 Bearer token 取得数据库内部 `user_id`，不允许客户端声明身份。API 写入管线请求时只包含内部 UUID，不把邮箱、用户名、Cookie 或令牌交给 Worker。

### 上传模块

上传模块使用独立 `job_uploads` 状态，不把半成品放进 `reconstruction_jobs`。它先把文件写入任务内 staging，识别并完整解码 JPEG/PNG，再以平台名称移动到 `input/images`。未提交阶段允许删图或取消；取消保留原因和清理审计，维护命令回收超时会话。提交时根据数据库元数据重新核对目录、大小和 SHA-256，写入 `input-manifest.json` 和管线请求，并在同一数据库事务中创建 queued 任务。不带请求体时仍默认 `simulated`；开发接口可显式提交 `{"execution_mode":"real"}`，由真实 Worker 独立领取。

### PostgreSQL 任务状态机

数据库保存任务状态、进度投影、错误码、租约和文件元数据，不保存图片或网格正文。调度器创建不可变 `pipeline-request.json`；Worker 通过事务租约取得一个任务后才调用当前适配器。事件 JSONL 是文件侧审计，数据库中的 `job_stages` 是面向查询和前端的状态投影。

### Worker 调度与心跳

数据库租约同时包裹 simulated 和 real 队列执行：取得租约后才启动执行器，心跳失败时拒绝提交终态，过期接管后旧 token 不能更新数据库。真实控制器持续检查租约、取消标记和总超时，任一条件触发时终止整个子进程树；恢复任务只能复用经过身份、大小和哈希复核的完整结果。

### Re3D 算法模块

适配器只传平台生成的 UUID、固定三分支、固定配置和任务内路径。Re3D v1.1.0 负责算法步骤；平台不允许用户上传命令、路径或任意参数。控制器已经实现子进程树取消、总超时、步骤事件、最小环境变量、产物收集、摘要校验和幂等恢复，并已完成 11 图真实小数据集运行；GPU/显存/磁盘资源采样仍待完成。

### 进度接口

Worker 把 Re3D 原始步骤映射为平台阶段，例如 `20-a-mapanything → a_inference`、`24-a-fuse → a_fusion`。后续 API 消费事件或数据库投影，通过 SSE 向任务页面推送；前端不解析 Re3D 自由文本日志。

### 产物与下载模块

真实执行完成后，适配器将 A-v4、B-v2、C 的 OBJ、MTL、纹理和 GLB 归一化到 `output/<branch>`，计算哈希并写入 `pipeline-result.json`。当前下载接口先按数据库任务所有者做对象级检查，再从经过契约验证的 `pipeline-result.json` 选择固定产物，并复核文件大小和 SHA-256 后返回。后续若迁移到对象存储，可在相同所有权边界后签发短期下载 URL。

### 自动评估模块

评估器读取 `pipeline-result.json`、SfM 指标、A/B 深度一致性清单和输出验证报告，生成 `reports/evaluation.json`。评估器不直接读取浏览器请求，也不改变重建产物。结果由 API 转成前端卡片和建议。

### 三维前端

现有前端使用相对 `/api` 路径、内存 access token 和 HttpOnly refresh Cookie，已实现受保护工作台路由。三维查看器从任务摘要选择可下载 GLB，用同一认证 Fetch 获取 Blob，再以短期对象 URL 交给 Three.js；切换分支时释放旧模型资源。模拟 Worker 的最小 GLB 会明确显示为空场景，真实模式继续根据 `execution_mode` 标识结果，避免把链路模拟当成重建质量证明。

### 清理模块

清理器使用与 `TaskLayout` 相同的 UUID 和规范化路径规则。失败任务在数据库终态落盘后删除整个任务目录；成功任务根据尚待确定的保留期处理。清理器不能接受前端传入的文件系统路径。

## 4. 为什么现在还不能直接公开提供真实重建

当前真实执行闭环已在本机 Re3D、CUDA 和 11 张实际图片上运行 COLMAP、MapAnything、MVSAnywhere 与 OpenMVS，并完成三分支产物及自动评估。该结果只证明单机开发闭环可执行。公开启用前还需要：

1. 补充 GPU、显存和磁盘资源采样，并审核真实日志的敏感信息边界；
2. 实现失败任务目录自动清理、成功任务保留期和最小审计；
3. 为稳定任务接口补充限流、配额、审计和反向代理安全验收，并将上传/提交切换为明确的生产策略；
4. 用有真值或人工标注的数据校准评估阈值，再决定是否提供综合质量分数；
5. 完成验证码、任务接口限流、审计查询权限、生产邮件服务和面向公网的部署加固。

因此当前实现仍不是可公开部署的最终重建系统；它已经把稳定任务访问 API、PostgreSQL 租约、独立 Worker、受控 Re3D 子进程、三分支产物、在线预览和结构评估连接成经过真实小数据集验证的边界。下一步应确定生产上传/提交策略，并补齐公网安全和运维边界。
