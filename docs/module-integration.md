# 当前实现的系统作用与模块对接

## 1. 当前实现处于哪一层

当前代码完成了 React 认证、真实图片上传到开发编排的基础闭环。它解决用户身份和会话、受保护前端路由、图片如何安全进入任务目录、任务如何被描述和持久化、Worker 如何独占资源、怎样验证输入、如何表示进度、结果和模拟评估。邮箱验证、上传清理和真实 GPU 执行仍未实现。

```text
React 前端（内容/认证/图片上传/任务列表已实现）
    │  HTTP/SSE
    ▼
FastAPI（注册/登录/会话及认证后的开发任务接口已实现）
    │  写任务、请求和模拟输入
    ▼
PostgreSQL 状态机/租约（已实现）
    │  Worker 原子领取、续租和状态推进
    ▼
Windows Worker
    ├─ 契约校验（已实现）
    ├─ 路径和输入完整性（已实现）
    ├─ 队列化三分支模拟执行与模拟评估（已实现）
    ├─ 真实 Re3D dry-run（已实现）
    └─ 真实 GPU 执行（未实现）
          │
          ▼
Re3D v1.1.0 A-v4 / B-v2 / C
          │
          ▼
真实产物归一化 → 正式评估 → API → 三维查看器（待实现）
```

## 2. 已实现模块的职责

| 当前模块 | 主要输入 | 主要输出 | 在完整系统中的作用 |
|---|---|---|---|
| React 前端骨架 | 用户导航和认证表单 | 会话状态、受保护页面 | 建立浏览器入口并固定令牌存储和 API 调用边界 |
| 上传服务 | multipart JPEG/PNG | 任务内图片、哈希与元数据 | 在入队前隔离、解码并校验用户输入 |
| JSON 契约 | API 任务数据 | request/event/result/evaluation 结构 | 固定前后端、Worker 和评估器共同语言 |
| 认证服务 | 注册和登录凭据 | 用户、access token、refresh session | 建立服务端可信用户身份和可撤销会话 |
| `TaskLayout` | 数据根目录、job UUID | 安全任务路径 | 保证用户任务文件隔离，限定清理边界 |
| 输入完整性校验 | manifest、图片、请求哈希 | 通过或稳定错误 | 防止排队后输入被替换或目录混入其他文件 |
| 模拟 Worker | simulated 请求 | 三个最小 GLB、事件、结果 | 让 API 和前端在 GPU 接入前完成联调 |
| 开发 FastAPI | 开发请求 | queued 任务、查询和取消响应 | 验证 HTTP 与任务边界；production 环境不注册这些路由 |
| PostgreSQL 队列 Worker | 队列记录、资源租约 | 状态投影、三分支产物 | 验证 API 与独立执行进程的异步闭环 |
| 模拟评估器 | simulated pipeline result | evaluation.json | 验证评估契约，不生成虚假的真实质量分数 |
| 真实 dry-run 适配器 | real 请求、Re3D 安装 | 步骤报告、私有命令日志 | 验证版本、参数、目录和三分支命令编排 |
| Re3D v1.1.0 目录接口 | work/output/log 精确路径 | 任务内运行文件 | 阻止不同用户任务散落或互相覆盖 |
| 原子写入与 SHA-256 | JSON、产物 | 完整文件和摘要 | 避免读取半文件，并支持篡改检测和幂等复用 |

## 3. 与后续模块如何对接

### 用户与鉴权模块

注册登录模块管理用户身份、密码哈希、短期 access token 和可轮换 refresh session。开发任务接口已经从服务端验证的 Bearer token 取得数据库内部 `user_id`，不再允许客户端声明身份。API 写入管线请求时只包含内部 UUID，不把邮箱、用户名、Cookie 或令牌交给 Worker。

### 上传模块

上传模块使用独立 `job_uploads` 状态，不把半成品放进 `reconstruction_jobs`。它先把文件写入任务内 staging，识别并完整解码 JPEG/PNG，再以平台名称移动到 `input/images`。未提交阶段允许删图或取消；取消保留原因和清理审计，维护命令回收超时会话。提交时根据数据库元数据重新核对目录、大小和 SHA-256，写入 `input-manifest.json` 和管线请求，并在同一数据库事务中创建 queued 任务。当前上传图片会进入模拟 Worker；真实执行尚未启用。

### PostgreSQL 任务状态机

数据库保存任务状态、进度投影、错误码、租约和文件元数据，不保存图片或网格正文。调度器创建不可变 `pipeline-request.json`；Worker 通过事务租约取得一个任务后才调用当前适配器。事件 JSONL 是文件侧审计，数据库中的 `job_stages` 是面向查询和前端的状态投影。

### Worker 调度与心跳

数据库租约已包裹 simulated 队列执行：取得租约后才启动模拟器，心跳失败时拒绝提交终态，过期接管后旧 token 不能更新数据库。真实 Re3D 接入仍需要进程控制器；租约丢失、超时或收到取消信号时必须终止整个子进程树。

### Re3D 算法模块

适配器只传平台生成的 UUID、固定三分支、固定配置和任务内路径。Re3D v1.1.0 负责算法步骤；平台不允许用户上传命令、路径或任意参数。dry-run 已证明目录和命令映射正确，真实执行还需加入子进程取消、超时、资源监控和产物收集。

### 进度接口

Worker 把 Re3D 原始步骤映射为平台阶段，例如 `20-a-mapanything → a_inference`、`24-a-fuse → a_fusion`。后续 API 消费事件或数据库投影，通过 SSE 向任务页面推送；前端不解析 Re3D 自由文本日志。

### 产物与下载模块

真实执行完成后，适配器将 A-v4、B-v2、C 的 OBJ、MTL、纹理和 GLB 归一化到 `output/<branch>`，计算哈希并写入 `pipeline-result.json`。下载接口根据数据库 `artifact` 记录和当前用户所有权返回文件或短期签名 URL。

### 自动评估模块

评估器读取 `pipeline-result.json`、SfM 指标、A/B 深度一致性清单和输出验证报告，生成 `reports/evaluation.json`。评估器不直接读取浏览器请求，也不改变重建产物。结果由 API 转成前端卡片和建议。

### 三维前端

现有前端使用相对 `/api` 路径、内存 access token 和 HttpOnly refresh Cookie，已实现受保护工作台路由。后续前端只通过 API 获取任务状态、评估和经过鉴权的 GLB 地址。模拟 Worker 生成的最小 GLB 可以提前开发加载器和分支切换；真实模式必须根据 `execution_mode` 显示真实结果，不能把 simulated 任务混入用户重建记录。

### 清理模块

清理器使用与 `TaskLayout` 相同的 UUID 和规范化路径规则。失败任务在数据库终态落盘后删除整个任务目录；成功任务根据尚待确定的保留期处理。清理器不能接受前端传入的文件系统路径。

## 4. 为什么现在还不能直接完成真实重建

开发闭环只运行模拟器；真实 dry-run 只证明命令会怎样执行，没有启动 COLMAP、MapAnything、MVSAnywhere 或 OpenMVS。正式启用前还需要：

1. 完成邮箱验证、密码重置、认证限流和审计；
2. 将已实现的 PostgreSQL 租约接入真实执行控制器；
3. 子进程生命周期、取消、超时和崩溃恢复；
4. 真实日志转事件和敏感信息过滤；
5. 产物复制、哈希、验证和结果汇总；
6. 小型图片集真实运行；
7. 失败任务目录清理与最小审计；
8. 产物、评估和下载 API。

因此当前实现不是最终重建系统，也不能公开部署；但前端认证、API、数据库、独立 Worker、三分支产物和评估文件之间已经形成可重复测试的边界。后续上传、任务页面和真实执行可以围绕稳定的用户 UUID、job UUID、任务目录和契约继续开发。
