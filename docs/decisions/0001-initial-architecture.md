# ADR 0001：首期平台架构与运行边界

- 状态：已接受
- 日期：2026-09-23

## 背景

现有 Re3D 已能在 Windows 环境运行 A-v4、B-v2、C 三条重建分支。平台计划面向公开互联网，但只用于非商业学习与工程实践。GPU 重建耗时较长，输入和中间数据体积较大，且第三方代码与模型存在各自的署名和非商业限制。

## 决策

1. Re3D 与平台使用独立 Git 仓库；平台固定调用标签 `re3d-pipeline-v1.0.0`。
2. 首期每个任务固定运行 A-v4、B-v2、C 三条分支，不向普通用户开放管线参数。
3. React 前端、FastAPI API 和独立 Worker 分进程运行；API 不同步执行 GPU 管线。
4. 首期使用 PostgreSQL 任务租约和心跳完成调度，单张 GPU 并发数固定为 1。
5. 原图、中间文件、日志、三个分支产物和评估报告统一存放在 `jobs/<job_uuid>` 下。
6. 失败任务在数据库记录终态和脱敏错误后删除全部文件；成功任务保留期待定，并作为公开部署前的阻断项。
7. 用户必须注册、验证邮箱并登录后才能提交任务；注册、登录、找回密码和任务提交均实施限流和配额。
8. 当前先在 Windows 上开发和验证；所有路径通过配置和路径库处理，不在业务代码中写死盘符。
9. 第三方声明以 Re3D 的 `THIRD_PARTY_NOTICES.md` 和固定 Git SHA 为同步来源。

## 影响

- 三分支会显著增加单任务 GPU 时间和磁盘占用，任务配额与磁盘预留必须在公开上线前通过实测确定。
- PostgreSQL 租约减少了首期组件数量，但必须实现事务领取、心跳续租和过期恢复测试。
- 按任务目录组织数据可简化权限和清理；删除逻辑必须验证规范化绝对路径位于 `Re3D-data/jobs` 下且末级目录为有效 UUID。
- 公开互联网部署需要额外完成 TLS、邮件投递、防滥用、备份、监控、隐私说明和数据保留策略，不能直接暴露当前本地开发服务。
