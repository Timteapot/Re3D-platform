## 2. 已实现模块的职责

### 本机 CPU 与服务器交接

这是独立实验数据交接，不是跨主机平台 Worker 或旧网页任务恢复接口。`hybrid_checkpoint.py` 用原静态输入清单绑定下载的最新一致性数据库，复核图像、相机、特征和既有图像对记录，再建立全新 `_experiments` 副本；不会改写原断点清单。

`scripts/run_hybrid_experiment.py` 默认仅准备。显式 CPU 执行由 `cpu_runner.py` 监督冻结管线的单个 `01-colmap` 阶段，`run_cpu_sfm_stage.py` 检查实际 CPU 提取/匹配和 Mapper 参数，复用 Windows Job、主机 RAM/磁盘保护、周期断点与 C 盘终态证据。CPU 档不构造 GPU 探针，也不检查或修改 PostgreSQL 队列。候选为提取/匹配 8 或 12 线程、Mapper/BA 16 线程；它与 40 逻辑 CPU/T4 服务器档分离。

`hybrid_handoff.py` 只接受通过完整 SfM 门禁的 CPU 结果。导出数据库、二进制/文本模型、实际参数、指标、配置与 SHA 清单；服务器导入重新验证输入和模型，在新实验目录保留导入前数据库与来源指标，仅重绑两项模型路径。导入返回 `02-extract-cameras`，但不调用 GPU、后续 OpenMVS、服务或任务接口；后续计算仍需单独接线和授权。C 分支及网格/贴图阶段也有 CPU 工作，不能把服务器剩余过程称为纯 GPU 运算。

新工具与源码 SHA 独立封装，避免平台包初始化、未固定模块或缓存字节码绕过工具源身份。导出/导入是文件一致性和格式门禁，不认证几何精度。操作前提与命令见 [本机 CPU 与服务器交接](hybrid-cpu-sfm.md)。

### 独立长测监督器

`backend/experiments` 是受限容量实验旁路，不改变现有 API、数据库任务状态机、Worker 租约或浏览器会话。新实验只恢复经过 SHA 和 SQLite 完整性验证的原图、预处理输入、掩码及 SfM 数据库；不复制旧阶段成功标记，不直接恢复旧网页任务。

入口 `scripts/run_long_experiment.py` 默认 `prepare`，不调用主机/GPU/数据库探测。显式执行须使用独立 SHA 绑定工具包，并通过 Windows 管理员、固定 40 逻辑 CPU/T4、运行时版本、磁盘与停止服务/只读队列门禁。单实例互斥防止两个长测同时启动。完整运行要求同源同配置的 8/12 线程准入报告：180 秒窗口、完整观察、CPU 整体及约 60 秒滚动均值不超过 80%、无资源告警、确证停树与断点、候选吞吐优于基线。该 CPU 规则是晋级门槛，不是操作系统限额或运行期 CPU 自动取消。

## 3. 运行时接口与扩展边界

### 用户与鉴权模块

注册登录模块管理用户身份、密码哈希、短期 access token 和可轮换 refresh session。登录前由 PostgreSQL 中的账户/IP 桶执行共享限流，注册前由用户名/邮箱/IP 桶限制有效尝试；认证结果写入仅含 HMAC/SHA 指纹和原因码的事件表，独立维护命令按保留期清理旧事件和闲置桶。稳定任务接口和开发任务创建接口都从服务端验证的 Bearer token 取得数据库内部 `user_id`，不允许客户端声明身份。API 写入管线请求时只包含内部 UUID，不把邮箱、用户名、Cookie 或令牌交给 Worker。

### 上传模块

上传模块使用独立 `job_uploads` 状态，不把半成品放进 `reconstruction_jobs`。multipart 解析后先按文件实际字节申请用户上传令牌和并发租约，再检查磁盘安全线，把文件写入任务内 staging，识别并完整解码 JPEG/PNG，复查剩余空间后以平台名称移动到 `input/images`。未提交阶段允许删图或取消；提交时重新核对目录、大小和 SHA-256，在同一事务中执行用户任务限额、把上传实际字节替换为任务固定预留、写入请求并创建 queued 任务。相同用户的容量和传输变更分别通过数据库用户行锁串行化；失败任务整目录清理或成功任务三层清理完成后释放存储预留。

### PostgreSQL 任务状态机

数据库保存任务状态、进度、版本、错误码、租约和上传文件元数据，不保存图片或网格正文。上传提交服务创建不可变 `pipeline-request.json`；Worker 通过事务租约取得任务后才调用适配器。细粒度步骤事件保存在 `manifests/pipeline-events.jsonl`，面向查询和前端的任务状态投影位于 `reconstruction_jobs`；当前没有独立 `job_stages` 表。

### Worker 调度与心跳

数据库租约同时包裹 simulated 和 real 队列执行：取得租约后才启动执行器，心跳失败时拒绝提交终态，过期接管后旧 token 不能更新数据库。真实控制器持续检查租约、取消标记和总超时，任一条件触发时终止整个子进程树；恢复任务只能复用经过身份、大小和哈希复核的完整结果。

### Re3D 算法模块

适配器只传平台生成的 UUID、固定三分支、固定配置和任务内路径。当前固定的 Re3D v1.1.3 负责算法步骤；平台不允许用户上传命令、路径或任意参数。控制器实现子进程树取消、执行预算监督、步骤事件、最小环境变量、产物收集、摘要校验、结果复用和资源采样。API 将预算冻结到请求，默认 3600 秒，direct-300 为 14400 秒；该预算约束管线子进程，不包含后续全部核验/评估耗时。真实小任务已通过服务器服务闭环，管线另有 150 图断点续跑证据；300 图容量、集中时序存储和阈值告警待验收或实现。

### 进度接口

Worker 把 Re3D 原始步骤映射为平台阶段，例如 `20-a-mapanything → a_inference`、`24-a-fuse → a_fusion`，并推进数据库状态投影。当前 API 的鉴权 SSE 定期读取任务状态向详情页发送更新；前端将更新写入 TanStack Query 缓存，并以普通 GET 轮询作为降级路径。前端不解析 Re3D 自由文本日志。

### 产物与下载模块

真实执行完成后，适配器将 A-v4、B-v2、C 的 OBJ、MTL、纹理和 GLB 归一化到 `output/<branch>`，计算哈希并写入 `pipeline-result.json`。当前下载接口先按数据库任务所有者做对象级检查，再从经过契约验证的 `pipeline-result.json` 选择固定产物并复核大小和 SHA-256，随后按完整产物大小申请用户下载令牌和并发租约；文件响应结束时释放租约。后续若迁移到对象存储，仍需在相同所有权与额度边界后签发短期下载 URL。

### 自动评估模块

评估器读取 `pipeline-result.json`、SfM 指标、A/B 深度一致性清单和输出验证报告，生成 `reports/evaluation.json`。评估器不直接读取浏览器请求，也不改变重建产物。结果由 API 转成前端卡片和建议。

### 三维前端

现有前端使用相对 `/api` 路径、内存 access token 和 HttpOnly refresh Cookie，已实现受保护工作台路由。三维查看器从任务摘要选择可下载 GLB，用同一认证 Fetch 获取 Blob，再以短期对象 URL 交给 Three.js；切换分支时释放旧模型资源。模拟 Worker 的最小 GLB 会明确显示为空场景，真实模式继续根据 `execution_mode` 标识结果，避免把链路模拟当成重建质量证明。

### 清理模块

清理器使用与 `TaskLayout` 相同的 UUID 和规范化路径规则。失败和取消任务经过宽限期后删除整个目录；成功任务的原图、中间文件和下载产物均按 30 天策略分层处理，并保留最小 manifest 和评估记录。持续 Worker 启动时及之后每 86400 秒只执行受审计 dry-run；实际删除只能通过独立命令同时传入 `--execute --confirm-delete`。两类清理都记录尝试、完成时间和稳定错误码，且不能接受前端传入的文件路径。

### 部署与运维模块

生产就绪检查读取 API/Worker 环境配置并验证数据库身份、秘密边界、Re3D 基线、SMTP、存储安全线和保留策略。安装前主机预检进一步检查 Windows/管理员状态、PowerShell/Node/Python/PostgreSQL 工具、WinSW/Caddy 固定版本、NVIDIA GPU、系统盘与数据盘、服务名和端口、数据库 TCP、公开 DNS 及待重启状态。服务包随后把 API、Worker、Caddy 分配给三个独立虚拟服务账户；安装后只读验收再检查进程、ACL、监听边界、TLS、发布提交和 Worker 队列循环。三层检查职责不同，不能互相替代。

受限部署在同一应用模块上增加单独的环境契约：API 入口、网页入口、可信代理、SMTP 和 PostgreSQL 连接均限定回环范围，API 不注册 development 路由且上传提交只允许 `real`。它使用独立 `re3d_platform_restricted` 数据库、`re3d_restricted_runtime` 角色和仓库外 `restricted` 数据根，避免验收数据混入开发库或未来生产库。目标服务器上的 Mailpit、API、Worker 和 Caddy 已以四个独立虚拟服务账户完成安装后基线验收；服务启动类型均为 `Manual`，云实例重启或节省停机恢复后需要显式启动并复核。回环 HTTP 下 refresh Cookie 必须为非 Secure；如果引入本机 HTTPS，URL 与 Cookie 标志必须同步切换。该例外只适用于回环访问或 SSH 本地端口转发后的回环访问，不可扩展到局域网或公网。

管理员审计查询复用认证模块返回的实时数据库角色，不把角色固化在 JWT 中。API 只读取四类审计表并返回有界分页投影；首名管理员由维护命令使用内部 UUID 提升，变更写入独立审计表并阻止降级最后一名活动管理员。当前接口与管理员前端、二次验证和集中告警尚未对接。

普通 API 限流中间件在业务路由前通过可信代理规则解析来源 IP，并在 PostgreSQL 中锁定对应 HMAC 桶。它覆盖认证、上传、任务、产物和管理员接口，但排除健康检查与浏览器预检。认证专项限流、任务提交限额和上传大小限制仍分别保留；这些策略处理不同风险，不能互相替代。

传输限制在认证后以用户 UUID 为维度运行。`user_transfer_buckets` 使用连续补充的字节令牌，`user_transfer_leases` 使用过期时间处理异常进程；上传完成校验/落盘或下载响应结束后释放租约。它不对连接执行 Mbps 整形，也不能在 multipart 解析前拒绝请求体，因此公网入口仍需连接数、请求速率、超时和大流量攻击防护。

## 4. 验收边界与公网前置条件

当前真实链路已在本机及目标服务器受限服务账户下完成 11 图任务，固定管线另已完成 150 图三分支断点续跑。这些证据分别说明小任务服务闭环和已有管线容量，不证明 300 图网页任务或公网安全。公开启用前还需要：

1. 将已有任务级资源样本接入集中存储和阈值告警，并审核真实日志的敏感信息边界；
2. 在目标服务器观察多轮 30 天保留策略 dry-run，并在备份确认后完成一次人工双确认删除与恢复验收；
3. 实测 Worker 任务空间峰值并校准已实现的存储预留，在目标服务器校准已实现的传输限额，并在现有反向代理边界上增加真实 SSE、并发上传、大文件下载及入口流量防护验收；
4. 用有真值或人工标注的数据校准评估阈值，再决定是否提供综合质量分数；
5. 完成验证码、管理员前端与二次验证、生产邮件服务、Windows production 服务实机验收和真实域名下的公网部署加固。

因此当前实现仍不是可公开部署的最终重建系统；它已经把 Caddy、稳定任务访问 API、共享来源 IP 限流、用户存储配额、PostgreSQL 租约、独立 Worker、受控 Re3D 子进程、三分支产物、在线预览、结构评估和数据保留审计连接成经过非公网拓扑与真实小数据集验证的边界。下一步在目标机通过容量预检后直接尝试一次 300 图，再封装部署与恢复流程；重启/故障恢复仍待验证。未来进入公网阶段时，另行部署不可变 production 发布目录并完成边缘防护、TLS 和真实域名验收。
