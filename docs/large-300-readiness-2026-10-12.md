# 300 图实验配置记录（2026-10-12）

## 结论

平台协议、上传链路、数据库约束、前端和 Worker 预检已经扩展到最多
300 张图片；这只表示代码可以表达和接收 300 图任务，不表示目标服务器
已经通过 300 图验收。

## 150 图证据

- Lighthouse 150 图在目标 Windows Server 与 Tesla T4 上完成 A-v4、B-v2、C
  三分支验证；
- 最终任务目录约 8.97 GiB，最终产物约 0.69 GiB；
- OpenMVS 日志记录的进程峰值工作集约为 4.13 GiB 和 4.35 GiB；
- 直接管线运行没有保存连续 GPU 显存峰值，也没有生成平台
  `storage-usage.json`，因此不能从本次结果证明 300 图显存和磁盘上界；
- COLMAP 使用穷举匹配，300 图的图片对数量约为 150 图的四倍。

## 暂定 300 图执行档

`gpu-large-300` 当前要求：

| 项目 | 暂定值 |
|---|---:|
| 图片规模声明 | 300 |
| 每任务空间预留 | 64 GiB |
| 任务完成后数据盘安全线 | 75 GiB |
| Worker 启动所需空闲空间 | 139 GiB |
| 单用户配额示例 | 128 GiB |
| 最低总显存 | 14 GiB |
| 启动时最低空闲显存 | 12 GiB |
| MapAnything batch size | 4 |

当前目标服务器数据盘总容量约 150 GiB，保留 150 图验收结果后空闲空间约
110 GiB，因此不能通过 `gpu-large-300` 的 139 GiB 启动预检。服务器受限部署
继续使用 `baseline`，不得将其就绪状态解释为 300 图容量通过。

## 后续验收顺序

1. 扩容数据盘，或者在本机 SHA-256 验证完成后由操作者明确确认清理旧服务器结果；
2. 使用现有资源监控器持续采集 GPU、CPU、内存、数据盘和任务目录；
3. 对同源数据依次运行 200、250、300 图，保持三分支串行和 batch size 4；
4. 使用 `report-storage-capacity` 汇总样本并校准 64 GiB 预留；
5. 完成 300 图后再决定是否将服务器受限环境从 `baseline` 切换到
   `gpu-large-300`。
